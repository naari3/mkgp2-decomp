# MKGP2 磁気カード: 読み書き・新規作成の実現可能性

調査日: 2026-11-07。根拠は mkgp2-decomp のソース (main 92c36d5) と main.dol (GNLJ82) のテーブル。
ツール: `mkgp2card.py`（同じフォルダ。デコード／新規生成／フィールド編集／送信フレーム生成）。

## 結論

- **データ側は完全に解けている。** カードの中身は 69 バイト (0x45) のビットパック。暗号化なし、署名なし、カード固有 ID なし、サーバー照合なし。
  守りは「先頭が `MKA`」「8bit 加算チェックサム」「VERSION」「COUNTRY=0」「名前の NG ワードチェック」だけ。
  なので、69 バイトさえ読み出せれば中身は全部読めるし、任意の内容の正しいカード像も作れる。
- **難しいのは物理層。** ゲームは 69 バイトの生データをカードユニット (RS-232 の別ユニット) に渡すだけで、
  磁気ストライプ上の符号化（どのトラック位置か、bpi、パリティ、ユニット独自のフレーミング）は**ユニットのファームウェア側**でやっている。
  この部分はゲームのコードからは分からない。
- だから現実的なルートは 2 つ。
  1. **本物のカードユニット（Sanwa 製と思われるリーダー/ライター/プリンタ）を入手して PC から直接叩く。**
     プロトコルは下記のとおりほぼ判明しているので、読み出し・書き込み・（たぶん）印字までできる。確実性が一番高い。
  2. **汎用の磁気カードライター (MSR605 系など) で生のビット列を読み、ユニットの符号化を逆算する。**
     旧カードが 1 枚あれば試せるが、ストライプ位置（JIS-II 表面ストライプなら MSR605 のヘッド位置と合わない）、
     保磁力、符号化方式が未確認なので、うまくいくかは読んでみないと分からない。

## カードユニットとの通信（デコンプから判明）

- ポート: Triforce の SCI2（"USE RS232C PORT#2"）。**9600bps、8bit、パリティなし、ストップ 1、CTS 使用**（`Sci2Port` コンストラクタのデバッグ出力どおり）。
- フレーム (`Sci2Card_BuildPacket`):
  `02 LEN CMD 00 00 00 <data...> 03 BCC`、LEN = 6 + データ長、BCC = LEN から ETX(03) までの XOR。
- 応答: 同じ形。`rx[3..5]` が ASCII のステータス 3 文字（`'0'` が正常系、`status2=='0' && status3!='2','5'` で成功扱い等）。
  読み出しデータは `rx+6` から 69 バイト (`Sci2Card_GetResponsePayload`)。
- コマンド一覧（全部ソースに出てくるもの）:

| CMD | デコンプ上の関数名 | 正しい意味 (YACardEmu 準拠) | データ |
|---|---|---|---|
| 0x10 | Sci2Card_SendCmdRetry | 初期化 | `'0'`/`'1'` |
| 0x20 | Sci2Card_SendCmdSpace | 状態取得 | なし |
| 0x33 | Sci2Card_SendCmdOptions | **磁気読み出し** | モード(`'0'`=69B 標準 / `'2'`=カード取り込み), ビット(`'1'`=8bit パリティなし), トラック(`'0'`=トラック1) |
| 0x40 | Sci2Card_SendCmdPing | キャンセル | なし |
| 0x53 | card_send_track_data | **磁気書き込み** | `'0'`,`'1'`,`'0'` + 69 バイト（8bit パリティなし、トラック1） |
| 0x7A | Sci2Card_SendCmdPrint | **外字フォント登録** | 長さ + 72B のフォントページ |
| 0x7C | Sci2Card_SendCmdRegister | **1 行印字 (PrintL)** | 即時/待機, バッファ clear/append, 種別(行位置), 文字列 |
| 0x7D | Sci2Card_SendCmdLedSet | **印字消去 (Erase)** | 開始行, 終了行 (1..23) |
| 0x80 | card_eject | 排出 | なし |
| 0xA0 | Sci2Card_SendCmdReset | クリーニング | なし |
| 0xB0 | Sci2Card_SendCmdCleaning | 新品カード払い出し (Dispense) | なし |

応答は `02 LEN CMD R P S <data> 03 BCC`。R=カード位置、P=エラー（`'0'` 正常、`'1'` 読み取りエラー、`'2'` 書き込みエラー、`'3'` ジャム、`'5'` 印字エラー…）、
S=ジョブ状態（`'0'` なし、`'2'` 不正コマンド、`'3'` 実行中、`'4'` カード待ち、`'5'` ディスペンサー空）。デコンプの status1/2/3 がそれぞれ R/P/S。
ゲームは返事を受け取るとき ENQ (0x05) を送り、ユニット側はコマンドを受けると ACK (0x06) を返す。
デコンプ側の関数名 (SendCmdPrint / Register / LedSet / Reset / Cleaning) は意味がずれているので、いずれリネームするとよい。

このコマンド体系は、湾岸ミッドナイト／頭文字D などの Sanwa 製カードリーダー (CRP-1231 系や CR-S31R 系) のエミュレータで知られている番号と同じ並びで、
**型番は確定: YACardEmu (https://github.com/GXTX/YACardEmu) の README に「Mario Kart Arcade GP / GP2 : CRP-1231LR-10NAB | 9600 none」とあり、デコンプの設定 (9600, パリティなし) と一致する。**

## カードデータ形式 (69 バイト)

ビット列は MSB 先頭（バイト 0 の bit7 がビット 0）。VERSION で 3 形式に分岐する:

- **VERSION 2 = MKGP2**（`lbl_8049B6A0`、73 項目、484 bit = 61 バイト使用、残り 8 バイトは 0）
- **VERSION 0 / 1 = MKGP1 の旧カード**（`card_unpack_legacy_dispatch_data_803FED70` / `card_unpack_legacy_dispatch_data_803FF0E0`）。MKGP2 は旧カードを読んで変換する (`card_unpack_legacy_dispatch`)。

V2 の主な配置（バイト.ビット）:

| 位置 | 項目 | bit |
|---|---|---|
| 0.0 | APP-CODE ×3 | 8 (`'M' 'K' 'A'`) |
| 3.0 | CHECKSUM | 8 |
| 4.0 | VERSION | 3 |
| 4.3 | COUNTRY | 1（**0 でないと弾かれる**: `isJapanese()` がこのビルドでは常に 0 を返す） |
| 4.4 | CAMERA-TAG | 1 |
| 4.5 | REMAIN | 6（残り回数） |
| 5.3 | UPDATE | 1 |
| 5.4 | NAME ×5 | 8（独自文字コード: 0=空白, 1..10=０-９, 英数・ひらがな・カタカナ・記号。表は 0x804E5590） |
| 10.4 | LAST_CHARA_TAG | 4 |
| 11.0 | LAST_KART_TAG | 1 |
| 11.1 | TITLE / 12.3 TITLE-PARAM | 10 / 3（称号） |
| 12.6 | VOLUME | 3 |
| 13.1 | WINS / 14.3 LOSE | 10 / 10 |
| 15.5 | GET-ITEM-LIST ×105 | 1 |
| 28.6 | LAST-GET-ITEM | 7 |
| 29.5 | COIN_MILAGE_TAG | 17 |
| 31.6 | ITEMPACK-1 ×3 | 7 |
| 34.3〜 | RESULT-GP-{50,100,150}-{MR,DK,WC,PC,KP,RB,YI,DN} | 各 4 |
| 46.3〜 | GHOST-* / WIN-GHOST-* ×4 | 1 |
| 54.3 | MISS-GP, PLAYCOUNT-TAG(6), TA-RECORD-*(タイムアタック記録), LAST-CLEAR-CUP-*, LIVE-TAG, RANKIN-TAG×5 | |

全項目は `python3 mkgp2card.py decode card.bin` で出る。

チェックサム: CHECKSUM バイトを 0 にした状態で 69 バイト全部を足して下位 8bit（`card_pack` / `fn_801D4DC0`）。

## 市販ハードについて

- **MSR605/MSR605X 等（ISO 3 トラック、裏面ストライプ用）**: カードのストライプが ISO 位置にあり、ユニットが既知の F2F で書いていれば生ビットは取れる。
  ただし MKGP のカードが JIS-II（表面中央、1 トラック 69 文字 = ちょうど 69 バイト）型だと、MSR605 のヘッド位置では読めない可能性が高い。
  69 バイトという容量は JIS-II の 69 文字と一致していて、この可能性はかなりある（推測）。
- **JIS-II 対応のリーダライタ**（国内の業務用品。手動スワイプ型もある）なら読める可能性があるが、
  8bit バイナリをユニットがどう符号化しているか（7bit+パリティでは 8bit データは入らない）を逆算する必要がある。
- **保磁力（HiCo/LoCo）、印字面（サーマル／リライト）**は未確認。旧カード実物を見るか、ユニットを入手すれば分かる。

## 次の一手（おすすめ順）

1. **旧カードの実物があるなら、まず MSR605 などで生読み（raw mode）を試す。** 何か出れば、ビット列から 69 バイトを探す。
   `MKA` (4D 4B 41) が出てくれば当たり。出なければ JIS-II 型の可能性が高い。
2. **カードユニット本体を入手する**（ヤフオク等で「三和ニューテック カードリーダー」「CRP-1231」「マリオカート カードユニット」）。
   PC の RS-232（9600 8N1, RTS/CTS）につなぎ、`mkgp2card.py frame 33` で読み出しフレームを送れば 69 バイトが返るはず。書き込みは `frame 53 card.bin`。
   ※ 実機ユニットの電源・DIP スイッチ設定はゲームごとに違うという情報あり。
3. 新規作成: ユニットさえあれば、`mkgp2card.py new` / `set` で作ったイメージを書き込めばよい。ブランクは同ユニット用の純正ブランクか互換品が必要。
4. 実機なしで遊ぶだけなら、PC で動くカードユニットエミュレータ（arcade-projects に MKGP2 用 Python 実装の報告あり）と組み合わせ、
   このツールでカードイメージを作る方法もある。

## 追記: 純正カードユニットと印字について (2026-11-07)

DOL 内の文字列とコードから分かること:

- ユニットは「CARD R/W」と呼ばれ、**磁気リーダライタ + 印字ユニット + カード払い出し機 (DISPENSER)** が一体になったもの。
  テストメニューには CLEANING / CARD DISPENSER TEST / PRINT TEST / RESTORE CARD PRINT / RENEW / READ-WRITE TEST がある。
  エラー表示は LINK / DATA WRITE / CARD JAM / PRINTER / SYSTEM / CARD EMPTY。
- **印字は書き換え式（リライトカード）と判断できる。** "REWRITE CARD COUNT"、"ERASE"、"RENEW" ("Your card must be renewed"、"RENEW A CARD FREE") の文字列がある。
  プレイのたびに表面を消して刷り直し、書き換え回数の上限に達したら新しいカードに移し替える（RENEW）流れになっている。
  磁気の REMAIN (6bit) は、この残り回数である可能性が高い（推測）。
- 印字のしくみ: 先に外字フォントのページ（最大 63 枚）を 0x7A で登録し、0x7D で消去、0x7C で 1 行ずつ印字する（通信の節の表を参照）。
  印字される中身は名前、称号、勝利数、カップの成績（50/100/150cc の順位）、集めたアイテム数、リトライ時のメッセージなど
  （`Sci2Card_Build*ReceiptLine`）。
- 初代の MKGP カードは GP2 用に書き換えられる（"If you rewrite this card, you cannot play MARIOKART ARCADE GP with it."）。
- 型番は DOL に書かれていない。Namco の Triforce/System 246 世代で使われた三和ニューテック (Sanwa Newtec) の
  CRP-1231 系（湾岸ミッドナイト 1/2 では CRP-1231LR-10NAB の報告あり）である可能性が高いが、未確認。

## 追記2: YACardEmu との照合 (2026-11-07)

- YACardEmu は CRP-1231LR-10NAB をエミュレートし、MKGP/MKGP2 を対応タイトルに挙げている。コマンド番号・フレーム形式・ステータスはデコンプと完全に一致。
- カード像は「69 バイト × トラック数」のファイル（3 トラックで 0xCF バイト）。MKGP2 はトラック1しか使わないので、
  `mkgp2card.py new/set` が出す 69 バイトの .bin をそのまま YACardEmu のカードとして使える（未実機確認）。
- 磁気の記録は「トラック1・8bit パリティなし・69 バイト」。ユニットは 3 トラックとも 69 バイト持てるので、
  JIS-II 表面ストライプではなく **ISO 位置の 3 トラック（高密度）** の可能性が出てきた。その場合 MSR605X 系の raw 読み（トラック1を 210bpi 設定）で読める見込みがある（推測）。

## 追記3: 頭文字D 用リーダー (CRP-1231BR-10) は使えるか / カードの入手 (2026-11-07)

- 頭文字D Ver.1〜3 のリーダーは YACardEmu の表で CRP-1231BR-10 (9600 even)。MKGP は CRP-1231LR-10NAB (9600 none)。同じ CRP-1231 系で、コマンド体系や 69B×3 トラックは共通。
- 違い: BR は応答の「カード位置」バイトがビットフィールド（シャッター状態などを含む）だが、LR は ASCII の `'0'`〜`'4'`。
  MKGP2 は `'1'`/`'2'`/`'3'` と比較している (`Sci2Card_IsStatus1OneTwoThree`) ので、**BR を筐体の MKGP2 にそのままつないでも正しく動かない可能性が高い**。
  パリティ設定も違う（DIP スイッチで変えられるという情報はあるが、LR 互換にできるかは不明）。BR にはディスペンサーがなく、シャッターがある。
- ただし **PC から直接叩いてカードを読み書きする用途なら BR でも十分な見込み**。磁気の読み書き (0x33/0x53) は同じなので、69 バイトの読み出しと書き込みはできるはず。
- カードの入手: (1) 使用済みの MKGP/MKGP2/湾岸 1・2 のカードを中古で買って上書きする（MKGP2 自身が初代カードを書き換える機能を持つので、上書き前提の運用で問題ない）。
  (2) 未使用ブランク（純正）をオークション等で探す。(3) 頭文字D/ダビスタのカードは「印字が消せない」という報告があり、
  リライト印字には向かないが、磁気だけなら使える可能性がある。汎用の磁気リライトカード（ロイコ式）は、サイズ・ストライプ位置・保磁力が一致するか未確認。

## 追記4: PC/Dolphin 前提での整理 (2026-11-07)

- **REMAIN = 書き換え残り回数で、磁気データの 6bit だけで決まる。** 新規/RENEW 時に 50 がセットされ (`CardRW_Renew_Page`)、
  1 プレイ終わるごとに 1 減る (`GameModeBase_Dtor` → `DecrementRemaining`)。0 になると印字フローで RENEW 案内の画面が出る (`CardPrintFlowUpdate` phase 10)。
  カード固有のカウンタやサーバー照合はないので、`mkgp2card.py set in.bin out.bin REMAIN=50` で書き戻せばリセットされる（最大 63）。
  中古カードの「使用制限」はこの値なので、磁気を書き直せば実質的に解除できる。ただし印字面の物理的な劣化は残る。
- **Dolphin は MKGP 用のカードリーダーを内蔵エミュレートしている** (`Source/Core/Core/HW/MagCard/`、YACardEmu ベース、C1231LR/C1231BR、トラック 69B×3)。
  ホストの実シリアルへ中継する機能は見当たらない（未確認）。なので Dolphin で遊ぶなら、
  「実カード → BR/LR ユニットを PC から直接叩いて 69B を吸い出す → .bin を Dolphin のカードとして使う」で足り、BR と MKGP2 の応答差を吸収するブリッジやパッチは不要。
  逆方向（Dolphin で更新した .bin を実カードへ書き戻す）も同じ。
- 実ユニットを Dolphin にリアルタイム接続したい場合だけ、Dolphin 側にシリアル中継を足し、さらに BR の位置バイト（ビットフィールド）を LR 形式（'0'〜'4'）へ変換する層が要る。

## 追記5: 実機リーダーを買ったときの進め方 (2026-11-07)

- カードはテレカと同程度の薄さ（ユーザー確認）。汎用品の候補は 0.188〜0.25mm の PET 磁気カード（プリペイド/回数券用）、印字もやるなら同厚の磁気付きリライトカード（ロイコ式）。
- MSR605X はスワイプ式なので薄いカードも通せるが、たわんで読みが不安定になりやすい。0.76mm のカードの裏に貼って厚みを足すと安定する。
- PC 側ツール: `cardrw_host.py`（PC がゲーム基板の役。ACK/ENQ の手順は Sci2Card_Tick どおり。未実機確認）。YACardEmu はリーダー側のエミュレータなので、実機を叩く用途には使わない。
- 手順: status → 旧カード read（`MKA` 確認、mkgp2card.py decode）→ readall で他トラック確認 → 同じ内容を write → 再 read で一致確認 → REMAIN リセットや新規作成 → .bin を Dolphin へ。
