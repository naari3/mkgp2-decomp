# ShellItem retrofit idioms (2026-08-10, batch_retrofit_shellitem)

1. CW switch `switch (x) { case 0: body; /* fallthrough */ case 1: rest; break; }` with the tail code *inside* case 1's body (not after the switch) eliminates the 2 spurious `b` that appear when case 1 is an empty break and the tail follows the switch. If the tail ends with an inner switch whose cases all return, put the post-switch code (e.g. Mtx44 default block) *after* the inner switch with no `default:` — it becomes the switch-end landing that the dispatch tree branches to directly, and case-1 `break` threads multi-hop to the shared epilogue (ShellItem_TickActive phase2/launchCmd guards).
2. Saved-GPR two-web swap (e.g. ItemCollision_Check result vs ItemAlias_HitRemapLookup result wanting r28/r29 reversed): local declaration order had zero effect (both orders produced the same coloring). Fixed by deleting the named local and nesting `(short)ItemAlias_HitRemapLookup(...)` directly as the callee argument — the anonymous cast temp gets a different web key/color than the named local web.
3. Call argument instruction scheduling (lfs/lwz/mr/li emission order in call setup) responds to the *extern declaration's parameter order*, not just the register marshaling: floats-first decl gave lfs-first scheduling; rewriting the decl as `(void *self, void *gabyou, int flag, float k1, float k2, float k3)` (same r3/r4/r5/f1/f2/f3 mapping) reproduced the target's load-first schedule for Item_RenderFlyingFromKart.
4. `unsigned char phase` local + `switch ((signed char)phase)` reproduces `lbz r4; extsb r0, r4` + later `addi r3, r4, 1` reuse; but the simpler direct form `switch (*(signed char *)(self + 0xc9))` + `*(unsigned char *)(self + 0xc9) = *(unsigned char *)(self + 0xc9) + 1` also matches — CW CSEs the byte load.
5. extabindex size fields self-heal once .text sizes match; a lingering extabindex % mismatch is a symptom of fn size drift, not an extab problem.
